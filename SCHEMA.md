# Robomotion Skills repository — on-disk schema

This document is the contract between three components that touch this
repo:

- **Designer marketplace** (`robomotion-new-designer`) — fetches
  `skills-index.json`, renders entries, writes the user's selection into
  the agent node's `optSkills` / `optActiveSkills` formData fields.
- **Deskbot pre-flight installer** (`robomotion-deskbot/skill`) —
  before each flow run, fetches each repo's tarball and extracts the
  `path` subtree into `~/.robomotion/skills/<owner>__<repo>__<name>/`.
- **Agent skill loaders** (`packages-main/src/agents`,
  `packages-main/src/hermes-agent`) — at runtime, read SKILL.md from
  that local install dir and inject it into the agent's system prompt
  (Hermes) or wrap it as an ADK `Skill` object (LLM Agent).

Both agent runtimes assume the content is already on disk; neither
fetches at runtime.

## Layout

```
skills/
├── SCHEMA.md                 ← this file
├── README.md
├── skills-index.json         ← Designer reads this to populate the marketplace
├── robomotion/               ← Robomotion-curated skills
│   └── <skill-name>/
│       ├── SKILL.md
│       ├── references/      (optional)
│       ├── scripts/         (optional)
│       └── assets/          (optional)
├── hermes/                   ← Vendored from Hermes upstream, organized by category
│   ├── <category>/
│   │   └── <skill-name>/
│   │       ├── SKILL.md
│   │       └── ...
│   └── ...
└── community/                ← Reserved for vetted community contributions (future)
```

Top-level namespaces (`robomotion/`, `hermes/`, `community/`) carry
governance / provenance, not behaviour. Skills behave the same regardless
of which namespace they live under.

## SKILL.md format

YAML frontmatter followed by markdown body. Both agent runtimes parse
the frontmatter for metadata and use the body verbatim as the
instructions block.

```markdown
---
name: arxiv-search
description: Search arXiv papers and download PDFs by ID.
version: 1.0.0
author: community
license: MIT
tags: [Research, Academic, PDF]
prerequisites:
  commands: [arxiv-cli]            # optional — binaries that must exist on PATH
compatibility: [hermes, llm]       # which agent runtimes can use this skill
---

# arXiv Search

Use the `arxiv` CLI to search papers, download PDFs, and …
```

### Frontmatter fields

| Field | Required | Notes |
|-------|----------|-------|
| `name` | yes | Stable identifier; must be unique across the index. Match the directory name. |
| `description` | yes | Single sentence; shown in the marketplace card. |
| `version` | yes | Semver. Used by deskbot for `.version` stamping (re-extract on change). |
| `author` | yes | `community`, `robomotion`, or a person's name/handle. |
| `license` | yes | SPDX identifier (`MIT`, `Apache-2.0`, …). |
| `tags` | no | List of strings; surfaced as filters in the Designer marketplace. |
| `prerequisites.commands` | no | List of CLI binaries that must be on PATH. Caller's responsibility to install. |
| `compatibility` | yes | `[hermes]`, `[llm]`, or both. Designer filters the marketplace by the agent type currently being edited. |

### Body

Free-form markdown. Both runtimes inject it into the agent's system
prompt (Hermes via `## Active Skills`, ADK via `Skill.instructions`).
Conventions:

- `## References` — prose pointers to docs the agent can read on demand
  via `references/<file>.md`.
- `## Scripts` — pointers to dispatchable helpers under `scripts/`.
- `## Examples` — concrete usage walk-throughs.

## skills-index.json

Top-level file the Designer fetches once on workspace open. Flat array
of entries, one per skill. Generated by the indexing script at the root
of this repo (see `tools/build-index.py`).

```json
{
  "version": 1,
  "name": "Robomotion Skills",
  "description": "Curated and vendored skills for Robomotion agents.",
  "skills": [
    {
      "name": "arxiv-search",
      "path": "hermes/research/arxiv-search",
      "description": "Search arXiv papers and download PDFs by ID.",
      "version": "1.0.0",
      "author": "community",
      "license": "MIT",
      "tags": ["Research", "Academic", "PDF"],
      "compatibility": ["hermes", "llm"]
    }
  ]
}
```

`path` is relative to the repo root. The Designer concatenates it onto
`https://raw.githubusercontent.com/<owner>/<repo>/main/` to fetch
SKILL.md for the detail view; deskbot's installer fetches the whole
repo tarball once per `(owner, repo, ref)` and extracts `path` from it.

## Install ID convention

Deskbot extracts to:

```
~/.robomotion/skills/<owner>__<repo>__<name>/
```

For this repo that becomes `robomotionio__skills__<name>` regardless of
namespace. Two skills with the same `name` in different namespaces would
collide; the indexing script enforces uniqueness across the whole index
to prevent that.

## File-extension allowlist (deskbot extractor)

Deskbot's tar extractor accepts only:

- Markdown: `.md`, `.markdown`
- Python: `.py`, `.pyi`, `.toml`, `.lock`
- JS/TS: `.ts`, `.tsx`, `.js`, `.mjs`, `.cjs`
- Config: `.json`, `.yaml`, `.yml`, `.sh`
- Text/data: `.txt`, `.csv`
- Images: `.png`, `.jpg`, `.jpeg`, `.svg`, `.webp`
- Extension-less: `LICENSE`, `README`

Anything outside the allowlist is silently dropped during extraction.
Don't ship binaries; declare them as `prerequisites.commands` instead.

## Adding a skill

1. Pick a namespace (`hermes/`, `robomotion/`).
2. Create the directory and write SKILL.md.
3. Run `python tools/build-index.py` (regenerates `skills-index.json`).
4. PR.
